# AI 带回计划经济｜课程预置与两轮选课集体规划仿真器

研究命题：**AI 能否通过降低分散信息的获取与协调成本，改变集中式资源规划的能力边界？**

本项目把它落成一个可运行、可检验、**能够失败**的程序：在有限课位、明确硬约束和制度优先级下，比较"现行机制""迭代式集体规划""AI 协调提案"的分配结果，用同种子、同随机情景的配对实验量化优化器、交互和 LLM 各自贡献了多少。

> **数据与制度边界**：系统全程使用**合成、已脱敏的模拟学生与合成课程**，不含任何真实浙大学生数据，也不是浙大现行选课规则的权威实现。输出是供学生确认的研究性**预置建议**，不写入教务系统、不锁定真实课位。

## 0. 先说结论（确认性复跑：独立新种子 41-80，2026-10-17）

**核心判据 E − F 未复现。** 判据在开跑之前写定于 [results/PREREGISTRATION_CONFIRMATORY_41_80.md](results/PREREGISTRATION_CONFIRMATORY_41_80.md)：主判据**只用独立新种子 41-80**，双侧精确符号检验 p < 0.05 记为复现，跑到 40 个种子为止，唯一允许的剔除是"该行 LLM 调用回退"。实测：

> **E − F = −4.48**（17 胜 18 负 0 平，有效 n = 35，非平局 35，门槛 24 胜，**p = 1.0**）→ 预注册判定：**未复现**。

批次 1-2（种子 1-40）那个 +35.04、27/13、p = 0.0385 就此降级为**未被独立样本支持的踩线波动**——它的留一法性质（"随便剔一个 E 胜场就变成 p = 0.0533"）在独立样本上直接兑现成了反面。

**复现成功的是与传统 OR 有关的两条**，且幅度接近：

| 比较 | 批次 1-2（种子 1-40） | 批次 3（种子 41-80） |
| --- | --- | --- |
| B − A（迭代规划 vs 现行机制） | +113.76 · 31/9/0 · p = 0.0007 | **+125.58 · 31/9/0 · p = 0.0007** |
| D − B（完整信息参照 vs 规则规划） | +87.95 · 32/8/0 · p = 0.0002 | **+84.10 · 28/12/0 · p = 0.0166** |
| **E − F（AI 提案 vs 规则提案，主判据）** | +35.04 · 27/13/0 · p = 0.0385 显著 | **−4.48 · 17/18/0 · p = 1.0 未复现** |
| E − B | +31.49 · p = 0.0533 | +1.85 · 16/19/0 · p = 0.7359 |
| E − B0 | +9.11 · p = 1.0 | +0.15 · 15/16/4 · p = 1.0 |
| B − B0（交互的净价值） | −22.37 · p = 0.047 **显著为负** | +1.24 · 18/17/5 · p = 1.0 **未复现** |
| C − B（LLM 选题 vs 规则选题） | −12.73 · p = 0.3323 | +6.14 · 11/7/19 · p = 0.4807 |
| F − B | −3.54 · p = 1.0 | +4.46 · p = 0.6358 |

**所以能被数据支撑的结论是**：在"协调提案"这个位点上用 AI 不会更好——E ≈ F，两批的点估计都在 0 附近（+35.04 与 −4.48，合并 1-80 为 +16.60、p = 0.1654），而 E 还要额外付出不可预测的 LLM 成本；规划能力的增益来自**迭代询问 + 精确求解**（B−A、D−B 两批稳健复现），不是来自模型。

五条限定，必须连着读：

1. **E 臂这一批有 5 行回退**（种子 46、53、63、72、74，均为 LLM 提案调用失败后回退到规则生成器），按预注册第 4 条整行剔除，因此主判据有效 n = 35、门槛由代码自动降为 24 胜；批次 1-2 的 E 是 0/40，C 臂另有 3 行回退（种子 57、67、70，1-40 是 12、17、39）。上游确实更不稳，但不能拿它解释方向差异：被剔除的是 E 而不是 F，且 F 臂一个 token 都不花。
2. **公平性指标也不站在 E 那边**：批次 3 的 p10 是 F 48.46 > E 48.34（1-40 里 E 47.90 是可部署臂最高），必修满足率 F 34.34% > E 34.11%。上一批写进 README 的"E 在公平性上更好"同样属于未复现的边缘结果。
3. **合并 1-80 只作探索性附注**：E − F = +16.60（44/31，p = 0.1654，有效 n = 75）。这批样本里前 40 个种子是看过结果之后才决定继续的，不能当主判据。
4. **硬约束与可复现性**：两批各 360 行，硬约束违规合计 0；求解器逐行 `OPTIMAL`、上下界差 0。确定性不是跨批对比出来的——1-40 与 41-80 没有共同种子——而是重跑验证的：种子 41、42、43 关掉 LLM 重跑一遍，A/B0/B/G/H/D/F 七个臂 × 9 个字段（含总效用、最差/最好情景、p10、必修满足率、询问数、轮数、违规数）逐项与批次 3 的原始行完全一致（脚本 `results_batches/determinism_check.sh`）。所以两批之间的差异来自场景抽取与 LLM，不是求解器抖动。

5. **本次复跑不是完全盲态**：预注册第 3 条写了"中途不查看部分结果"，但首次尝试被 WSL 重启打断后，我在评估损失时从残留日志里看过那 32 个种子的 E/F 效用方向。那批数据随后整体作废、未参与任何统计（日志无法重建每行的回退标记，剔除规则执行不了），但"看过一次"无法撤销，所以这条偏差如实记录在预注册文件第 8 节，判定结果的表述按"未复现"而非"盲态确证的无效"来读。

另外保留一条上一轮的自查结果：**H 臂"获取信息不改预置"在实现上是 B0 的复制品**（两批共 80 个种子上效用与最差情景效用逐个相等，由 `results_batches/h_vs_b0_check.py` 逐种子核对），它只分离出沟通成本，没有分离"信息"与"重新优化"；不要把 B−H 当成独立于 B−B0 的第二条证据。

**第三个 AI 位点（语义需求解析 J）也已判完，同样没过线**：独立测试种子 7-26 的预注册符号检验给出阴性判定，而且需求识别质量上 AI 解析明显低于规则解析。数字、读法与"为什么这不等于规则做不到"都在 §7B，判定原文由 `verdict_splice.py` 从 `results_semantic_need/FROZEN_VERDICT.md` 拼接进来、`verdict_readme_guard.py` 逐行核对，本节刻意不重抄一遍数字。补全需求模型字段后的第二处理 I2/J2/K2 判完得出了同样的方向：**主判据仍未过线，按预注册读作阴性结果**，判定已于 2026-10-18 10:19 落盘并逐字搬进 §7C 与 §9（同样由 `verdict_splice.py --suffix _V2` 拼接、`verdict_readme_guard.py` 逐行核对，本节不重抄数字）。两条判定独立成文，不合并成一句"AI 有用/没用"：它们检验的是两个不同的处理，换的是不同的东西。

## 1. 安装与启动

要求 Python 3.10+。请在项目内创建独立虚拟环境，不要使用全局解释器。

### Linux / macOS / WSL

```bash
python3 -m venv .venv
.venv/bin/python -m pip install --upgrade pip
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m streamlit run app.py
```

浏览器打开 `http://localhost:8501`。左侧默认参数（72 名学生、种子 7、预算 30 问、每轮 4 问、规则控制器）直接点击**运行集体规划仿真**即可跑通全流程，不需要任何 API key。

### Windows

```powershell
py -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
streamlit run app.py
```

`run.bat` / `run.sh` 是等价的快捷脚本。依赖为 `streamlit`、`pandas`、`requests`、`python-dotenv`、`ortools`；界面用 `width="stretch"` 控制表格与按钮宽度，所以 `requirements.txt` 把 Streamlit 下限设到 1.66（实测 1.66.0）。未安装 OR-Tools 时引擎自动使用贪心回退，仍可运行，但正式实验必须记录求解器版本与状态。

### 配置 LLM（可选，一次性写进文件）

复制 `.env.example` 为 `.env` 并填写：

```
OPENAI_BASE_URL=https://api.openai.com/v1
OPENAI_MODEL=gpt-4.1-mini
OPENAI_API_KEY=sk-...
LLM_REQUESTS_PER_MINUTE=20
```

`.env` 已在 `.gitignore` 中；密钥不会被提交，也不会出现在日志、导出文件、`results/` 或 LLM 提示词里。侧边栏"LLM 连接设置"的三个输入框从 `.env` 预填，可临时覆盖，值只存在于本次页面会话内存中。**没有 API key 时系统照常运行**——默认规则控制器不调用任何远程模型；选择 LLM 控制器或 LLM 提案臂而未配置密钥时会明确报错，不会静默降级成假数据。

`LLM_REQUESTS_PER_MINUTE` 是上游配额，控制器在本地做滑动窗口节流，并按 `Retry-After`／指数退避重试最多 5 次；设 0 关闭节流。任何一次回退到规则策略的运行都会被标记 `llm_fallback` 并剔除出 AI 结论，所以扩种子前先确认这个值与账号实际配额一致。

### 求解器可复现性

| 环境变量 | 默认 | 作用 |
| --- | --- | --- |
| `SOLVER_WORKERS` | 1 | CP-SAT 搜索线程数。设 1 才能让同种子逐次复现 |
| `SOLVER_MAX_SECONDS` | 6 | 单次求解时限 |

本报告 360 行结果中，经过求解器的 280 行（B0/B/C/E/F/G/H）状态全部为 `OPTIMAL`、上下界差 0；A 与 D 不走 CP-SAT，因此没有求解状态。多线程时同一种子可能停在另一个等价最优解上（历史上 B 臂 seed 2 相差 19 点），因此结论只看配对差值，不看单次绝对值。

## 3. 数据契约与隐藏信息隔离

三张表 + 一个清单，读写与校验实现见 `data_io.py`：

- `courses.csv`：`course_id, course_name, category, time_slot, capacity, topics, prerequisites`
- `students.csv`：`student_id, year, priority_group, priority_tier, interests, target_courses, required_courses, completed_courses, declared_courses, initial_scores`
- `simulation_truth.csv`：`student_id, true_scores` —— **隐藏真值**，第一行是 `#READ_ONLY` 警告
- `manifest.json`：`seed / n_students / n_courses / provenance`

多值字段用 `|` 分隔，分数用 JSON 对象。缺列、ID 重复、引用不存在的课程、志愿缺可见分数等情况都会在导入阶段抛出 `DataContractError`，不会静默继续。

隔离规则：

- 规划器与 LLM 只看到 `initial_scores`（学生初始声明）、已声明志愿、公开兴趣线索、`.skill` 学习记录、培养要求、容量与时段。
- `true_scores` 只用于两件事：模拟学生回答"是否接受替代课程/是否确认提案"，以及实验结束后离线计算效用。
- 提示词构造函数只接受可见字段。这条由三处测试守着，边界各不相同：`test_llm_controller.py::test_payload_contains_no_hidden_scores` 在 HTTP 请求体那一层核对提案/控制器通道；`test_semantic_needs.py` 核对 v1 需求解析；`test_semantic_needs.py::JPromptCarriesNoHiddenTruth` 与 `test_semantic_needs_v2.py::J2PromptCarriesNoHiddenTruth` 分别核对 v1、v2 需求解析**真正发出去的请求体**——两者共用 `tests/prompt_isolation.py`：把 `true_scores` 换成全局唯一哨兵，只替 `llm_controller._chat`、让生产代码自己组装载荷，然后正反两侧核对（每名学生的 `.skill` 原文必须逐字、恰好一次出现；字段名 `true_scores`、任何学生的完整效用表、任何哨兵数字、API key 必须不出现）。配套 `tests/_selftest_prompt_isolation.py` 对两条臂各施加 8 个泄漏形状的变异（共 16 个），证明这条核对真的会报警。✓ 学生级导出不含 `true_scores` 由 `test_app_semantic_tab.py::test_6` 逐列核对。
- 学生是否接受由确定性阈值（`ACCEPT_THRESHOLD = 48`）从隐藏分数生成，**不是 LLM 自评**。所有指标由代码计算。

## 4. 评价流水线

```
合成世界(seed) → 需求模型(needs.py) → 预置求解(planner_core.solve_assignment)
  → 协调/提案迭代(controller 或 proposals) → 两轮选课模拟(selection_sim.simulate_selection)
  → 在最终课表上离线评价(evaluate)
```

关键一点：**评价对象是两轮选课之后的最终课表，不是预置表本身**。每个预置方案重放 `--sim-replicates`（默认 3）个配对随机情景，取均值/最差/最好。这正是 §0 里 B − B0 从 +257 变成 −22.37 的原因：预置的错误会被抽签和第二轮补选修掉一部分，只评价预置表会高估所有干预的收益。

制度规则（优先级分组顺序、同类型/跨类型冲突、抽签、第二轮顺序、预置是否占位）集中在 `institution.py`，每条都带依据分级（发起人描述 / 系统假设 / 官方核实）。报告 §2 会把整张规则表连同依据一起打印——**标注为假设的规则一旦与真实制度不符，结论必须重跑**。

## 5. 十二条机制臂

同一个种子生成**同一个世界**（相同课程供给、学生样本、初始声明、制度约束、询问预算与随机情景），十二条臂分别运行：

| 臂 | 机制 | 隔离出的问题 |
| --- | --- | --- |
| A | 现行机制基线：培养方案只推荐必修，随后完整执行两轮选课 | 抽象基线能到什么水平 |
| B0 | 一次性优化，零交互 | 优化器本身值多少 |
| B | 规则式集体规划：透明规则控制器 + 预算内询问 | **交互本身**值多少 |
| C | AI 集体规划：LLM 在 B 的候选问题集与预算内挑问题 | LLM 选问题比规则**额外**加了多少 |
| D | 完整信息参照：隐藏偏好全部公开 | 信息缺口上限（不可部署，仅作参照） |
| **E** | **AI 协调提案**：LLM 读全局状态与学生记录，生成结构化提案 | **AI 能否提出传统规则没表达过的集体协调方案** |
| **F** | **规则协调提案**：规则生成同类提案 | E 的单变量对照 |
| G | 等预算随机询问 | 分离"询问数量"与"问得准" |
| H | 获取信息但不改预置 | 想分离"信息"与"重新优化"——**实现上是 B0 的复制品**，见 §9 |
| **I** | **规则语义需求解析**：`.skill` 文本 → 学习目标/课程相关性，全部由关键词与培养规则推导，零 API 成本 | 需求理解位点的**可部署基线** |
| **J** | **AI 语义需求解析**：同一 schema 下由 LLM 读 `.skill` + 课程描述 + 培养要求产出相关度、依据与不确定性 | **AI 理解需求比规则额外加了多少**（本轮主判据 J − I） |
| K | 隐藏真实需求标签参照 | 需求解析位点的**不可部署上限**：就算解析全对，能拿到的收益上限在哪 |

I/J/K 只改变进入优化器的**需求输入**，其余全部与 B0 同构：同一个 `solve_assignment`、同一份合法性映射、同一个采纳阈值 `RELEVANCE_ADOPT_MIN = 0.35`、同一组配对随机情景（`seed * 1000 + 17`），且**三臂都问 0 个问题**——把交互变量彻底拿掉，只留"谁把需求翻译成课位"。培养硬约束（`required_courses`、容量、时段互斥、先修）一律由 `hard_requirements()` 用规则生成，LLM 无权改动，违反这一点会被 `validate_relevance` 拒绝并整条丢弃。实现见 `semantic_needs.py`，实验接线见 `experiments.py` 的 `NEED_ARMS`。

### E 与 F 为什么是干净的单变量对照

两臂共用：同一份规则解析的需求模型、同一个合法性校验器、同一个执行器、同一个 CP-SAT 优化器、同一询问预算、同一组随机情景种子。**唯一变量是"由谁决定为谁组合、如何排序、何时停止"**。因此若 E 未稳定优于 F，只能说明提案机制本身可运行，不能说收益来自大模型。LLM 语义需求模型（J 臂）**不参与 E/F 对照**，它在 I/J/K 这组三臂里单独测——两组实验分别冻结，避免"需求理解"和"提案生成"两个变量同时变化。

### 合法性对称与修剪

- 控制器可见状态为每名未满足需求的学生给出 `admissible_course_ids`（可直接询问的课程）与 `admissible_swaps`（需先释放冲突课程才能询问的课程对）。这两份清单与校验器使用**同一套可见规则**——信息对称，AI 不靠偷看合法性取胜。
- 校验器独立判定每个动作：非法动作逐个丢弃（`actions_rejected`），保留其余合法动作（`proposals_pruned`），全部非法才整案拒绝（`proposals_rejected`）。`proposals_valid` 的口径是"至少保留一个合法验证动作"，不是整案完全合法。
- 提案字段是白名单结构化的，不含 `capacity`、`true_scores` 等禁止字段；**AI 永远不分配课位**，它只提出"去问谁、换哪门课"，最终分配仍由优化器在硬约束下完成。
- 学生确认环节由确定性阈值从隐藏分数生成，AI 不能替学生点头。

**这条对称性是被逼出来的。** 第一版实现没把合法性事实交给控制器：8 个种子共生成 36 份提案，只有 1 份通过校验且未获学生确认，E 的最终效用与 B0 在全部 8 个种子上**完全相同**（已逐行核对）。该运行归档在 `archive_rejected_action_space/`，作为"控制器缺少合法性信息时，提案机制退化为空操作"的失败记录。

## 6. 指标与统计口径

| 指标 | 计算方式 |
| --- | --- |
| 最终总偏好效用 | 两轮模拟后每名学生最终课表的 `true_scores` 求和（跨情景取均值） |
| 最差/最好情景总效用 | 3 个随机情景中的最小值/最大值，看方案对抽签的鲁棒性 |
| 平均学生效用 | 总效用 / 学生数（未获课位者按 0 计） |
| 低分位(p10)学生效用 | 学生效用升序第 10 百分位，观察是否有群体被牺牲 |
| 关键需求满足率 | 被满足的 `required_courses` 条目 / 全部必修条目 |
| 最终课表接受率 | 最终课表中每门课隐藏分数都 ≥ `ACCEPT_THRESHOLD` 的学生占比 |
| 志愿额度达成率 | 实际分配课位数 / 学生声明的修读上限 |
| 课位利用率 | 已占用课位 / 总课位 |
| 预置保留率 / 调整率 | 学生在两轮中保留预置课程的比例；主动改动的比例 |
| 第一轮录取数 / 第二轮补选数 | 两轮各自的分配规模 |
| 两轮后必修未满足数 | 最终仍缺的必修条目总数 |
| 硬约束违规数 | 容量 + 最终课表时段冲突 + 先修资格违规之和，**必须为 0** |
| 询问次数 / 有效询问次数 / 规划轮数 | 交互成本；有效询问指真正改变了可见分数的问题 |
| 提案数量 / 通过校验 / 被修剪 / 被丢弃动作 / 获确认 | 提案漏斗，逐级可见 |
| 每次有效询问的增量效用 | (本臂效用 − B0 效用) / 有效询问数 |
| 与完整信息参照的效用差距 | D 的总效用 − 本臂总效用 |

统计口径：配对差值在同一种子、同一组随机情景上相减，报告均值、标准差、标准误、t 值、胜/负/平计数，以及**精确双侧符号检验 p 值**（用 `math.comb` 直接算二项分布，不做正态近似，小样本下近似会给出假的显著性）。

**总效用更高不等于更公平；课位利用率更高也不等于配置更好。** 报告把 p10 与必修满足率单列，正是为了让"谁被牺牲"看得见。p10 目前仍是加权目标的一部分，尚未实现词典序保护。

诚实声明：

- **不能归因于回退剔除**：批次 3 被整行剔除的是 E 的 5 行而不是 F 的任何行，剔除会移除 E 的样本而非制造负值；且这 5 行是回退到规则生成器，等价于 F 的策略，即便保留也只会把 E 拉向 F 而不是拉高它。
- **公平性指标同样不站在 E 那边**：批次 1-2 里 E 的 p10（47.90）是可部署臂最高、必修满足率 34.67% 九臂最高；批次 3 反过来，p10 是 F 48.46 > E 48.34，必修满足率 F 34.34% > E 34.11%，E−F 的 p10 差值从 +0.23 变为 −0.23。上一版写进 README 的"E 在公平性上更好"属于同一批未复现的边缘结果。
- **E 的成本两批都不可预测**：询问 12.97 ± 7.52（1-40）与 12.54 ± 7.73（41-80），F 为 16.18 ± 2.69 与 15.4 ± 2.96；规划轮数 E 2.9 ± 1.26 与 3.2 ± 1.85，F 5.62 ± 0.73 与 5.4 ± 0.83——LLM 自己决定何时停止，所以每次有效询问的增量效用（E：+0.59 ± 22.55 与 −1.38 ± 17.17）方差比均值大。按种子折算约 4 次调用、5.9 万提示词 token。
- **只有 OR 那条线是稳的**：B − A、C − A、D − B、D − E 在两批独立样本上都显著且幅度接近，即"迭代询问 + 精确求解"和"信息缺口本身"可复现；把 LLM 换成规则（C vs B、E vs F）在两批里都分不开。
- **交互的净价值这条也翻车了**：批次 1-2 的 B − B0 = −22.37（p = 0.047，显著为负）在 41-80 变成 +1.24（18/17/5，p = 1.0）。合起来读：迭代询问相对零交互基线**没有稳定方向**，既不显著更好也不显著更差。
- **上游端点变的不只是速度**：批次 2（31-40）慢约 8 倍，3 次 C 回退全为 `SSLEOFError`；批次 3 的 E 臂 5 次回退（12.5%）。中途没有改过超时、重试次数或限流参数——那会改变处理条件，跨批比较就失效。
- 单轮评价的旧结果（B − B0 = +257、D − B = +607）归档在 `archive_single_round_baseline/`；被否决的空操作 E 臂归档在 `archive_rejected_action_space/`；扩样本前的 30 种子中间态归档在 `archive_30seeds/`（当时 E−F = +43.25，20/10，p = 0.0987，判定不了）。三份归档加上 `results/PREREGISTRATION_CONFIRMATORY_41_80.md` 与批次 3 首次尝试的作废日志，构成本项目结论反转的完整证据链，没有删除。

## 7B. AI 语义需求解析（I/J/K）：实现状态与开发集实测

新模块 `semantic_needs.py`（`PARSER_VERSION = semantic-need-v1`）把学生 `.skill` 原文、官方课程描述与培养要求一起交给模型，要求返回**结构化**的学习目标、逐课相关度（0–1）、逐字摘录的证据、不确定度、可接受替代项与需求类别。每条返回都要过 `NEED_OUTPUT_SCHEMA` 校验和 `validate_relevance`：证据必须在学生原文里逐字找得到、先修不合格的课直接被拒、相关度低于 `RELEVANCE_ADOPT_MIN = 0.35` 的推断不进优化器，未采纳的推断逐条留痕可查。培养硬约束（必修清单、容量、时段互斥、先修资格、每人课位数）始终由 `institution.hard_requirements()` 与优化器决定，模型无权修改任何一条；隐藏真实偏好 `true_scores` 从不进入提示词。三臂只在**需求输入**上不同：I 规则解析（关键词 + 手工别名表）、J AI 解析、K 隐藏真值标签（不可部署的上限参照），共用同一个 `solve_assignment`、同一批容量与同一组配对随机情景。

- **效用是模拟量纲**，来自合成分数，只做机制间相对比较，不可解释为真实满意度。
- **模拟学生答复是确定性阈值**且默认诚实，不含策略性隐瞒，因此询问收益是模型上限而非真实现场；真实部署必须换成学生本人回答或授权数据。
- **公平性仍是加权目标的一部分**，尚未实现词典序或分层优化来显式保护 p10 学生。
- 未接入真实教务数据源，无鉴权、无多用户、无持久化，仅供本地研究演示。真实学生试点必须先做数据最小化与访问控制。
- 询问预算按问题数计，未按 token 或费用做硬预算；`summary.json` 记录了 token 用量供事后核算。
- **限流是本地单进程窗口**，不共享多进程/多会话配额；账号配额若在别处也被消耗，仍需下调该值。
- **上游端点不稳**：批次 2（31-40）慢约 8 倍、C 臂 3 次 `SSLEOFError` 回退；批次 3（41-80）C 臂 3 行、**E 臂 5 行**回退。中途没有改过超时、重试或限流参数，所以跨批可比；但继续扩样本会让 AI 臂的有效样本持续缩水（E 已从 40 缩到 35）。长跑还需要解决"只在收尾落盘"这一条——批次 3 首次尝试就是被一次 WSL 重启清空了 32 个种子的逐行数据。
