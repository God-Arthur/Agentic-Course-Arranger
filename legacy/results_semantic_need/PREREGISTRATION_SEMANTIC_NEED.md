# 预注册：语义需求位点（I 规则解析 / J AI 解析 / K 真值参照）

登记时间：2026-10-17 06:37（WSL 本地时间）。本文件在任何 J 组数据被读取之前写入并冻结。
凡与本文件冲突的事后解释，一律以本文件为准并如实标注为偏离。

## 1. 研究问题

学生 `.skill` 记录改写为自然语言后，用 LLM 做语义需求解析（J），是否比用关键词/别名规则解析（I）
生成**更好的预置课表**，并在完整两轮选课后得到更高的最终效用？

这是一个新的位点：I 与 J **一个问题都不问**，只改变"进入优化器的需求清单从哪来"。
它与已经关闭的 C（挑问题）与 E（协调提案）位点正交，不得互相引用结论。

## 2. 单变量控制

I 与 J 共用以下全部要素，唯一差别是解析器：

| 要素 | 取值 |
| --- | --- |
| 学生与课程 | 同一 `generate_world(n_students=72, seed=s)` |
| 硬约束 | 先修资格、容量、时段、必修清单，全部由规则系统判定；`validate_relevance` 拒绝越界推断 |
| 进入优化器的接口 | `predicted_visible`：同一映射 `分数 = 40 + 55 × 相关度`，同一采纳阈值 0.35，同一每人至多 8 门 |
| 优化器 | 同一个 `solve_assignment`（CP-SAT，workers=1，max_seconds=6） |
| 评价对象 | `simulate_selection` 两轮后的最终课表，配对随机情景 `seed×1000+17+i`，replicates=3 |
| 询问预算 | 两臂均为 0 次询问 |

K 用隐藏真值标签，但走**完全相同**的接口与上限，因此它是"同一接口下的完美解析器"上限，
不是可部署机制，也不是 D（披露全部真实分数、直接改目标函数）。隐藏真实偏好从不进入 I 或 J 的提示词。

## 3. 情景分离

## 4. 主判据与停止规则

- **主判据**：J − I 的最终总效用，只在测试种子 7-26 上计算，双侧精确符号检验，p < 0.05 判定为"AI 语义解析有增益"。
  20 个非平局对至少需要 **15 胜**（`_sign_threshold(20)`）才过线。
- **次要判据**（只做描述，不做显著性宣称）：需求识别 F1、重要需求最终满足率 `key_need_fulfillment_pct`、
  p10 学生效用、硬约束违规数、运行成本（调用数、token、缓存命中）。
- **停止规则**：跑满 20 个测试种子即停止，无论 p 为何值都不追加种子。
- **唯一允许的行剔除**：`llm_fallback=True` 的 J 行（回退后即规则策略，不能作为 AI 证据）。
  剔除数量与种子编号必须披露。

## 5. 功效声明

n=20 时符号检验只能检出很强的效应；若 J−I 的点估计小、±2SE 跨 0，则结论是"本设计测不出差异"，
而不是"无差异"。若 J 未过线，如实报告为阴性结果，不得改换指标、不得追加种子、不得重新解释为"部分有效"。

## 6. 已知风险与事前声明

1. **稻草人风险**：I 的别名表若恢复不了任何改写说法，J 的胜利没有意义。
   `rule_alias_coverage()` 公开每张说法的可恢复性；已用单元测试固定"部分可恢复"（1 到 6 个主题）这一条件。
2. **反向退化风险**：现有 `.skill` 是结构化文本，规则可无损解析，那才是真正无法测量的对照。
   本实验把记录改成散文，就是为了制造可核查的语义鸿沟；这一点必须在报告里写明，
   并声明"规则系统同样可以人工扩充别名表"，因此测得的是**免手工维护的泛化能力**，不是"规则做不到"。
3. 上游 LLM 配额 20 次/分钟，`semantic_cache/llm_relevance.jsonl` 按学生档案键写穿缓存，
   崩溃重启不重复计费；不同种子产生不同学生档案，缓存只在同种子重跑时省钱。
