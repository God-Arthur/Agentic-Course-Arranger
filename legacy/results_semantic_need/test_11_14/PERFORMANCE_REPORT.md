# 对照实验性能报告

- 生成方式：`python run_experiments.py`（全部指标由代码计算，LLM 不参与打分）
- 每组配置：72 名合成学生 / 随机种子 [11, 12, 13, 14] / 信息预算 30 次询问 / 每轮 4 题 / 每个方案重放 3 个配对随机情景
- 评价对象：预置方案经过第一轮与第二轮选课之后的最终课表，而不是预置表本身
- 运行时间：2026-10-17 18:30:35
- 求解器：引擎 cp-sat（缺失时贪心回退），单工作线程（1）、时限 6.0 秒，逐行记录状态、目标值与上下界
- 数据：合成数据，不含任何真实学生记录

## 2. 制度规则与行为参数（依据分级）

本轮结果只在下列规则成立时有效。凡标注为假设或未经官方核实的规则，都必须在真实数据上重新核对后重跑。

| 规则 | 取值 | 依据 | 说明 |
| --- | --- | --- | --- |
| max_preferences_per_category | 3 | 发起人描述，未经官方核实 | 同一类型课程最多三个志愿。 |
| same_category_conflict_allowed | 是 | 发起人描述，未经官方核实 | 同类型冲突课程仍可作为候选志愿。 |
| cross_category_conflict_allowed | 否 | 发起人描述，未经官方核实 | 不同类型课程之间不允许志愿时间冲突。 |
| final_timetable_conflict_allowed | 否 | 系统假设 | 最终课表不得存在实际时间冲突；提交允许与最终允许分开处理。 |
| prerequisites_enforced | 是 | 系统假设 | 先修资格是制度硬约束，与规划策略无关。 |
| priority_group_order | 毕业年级、即将换校区、转专业、其他学生 | 系统假设 | 发起人提到毕业年级、即将换校区、转专业等类别，但官方顺序与组内划分未核实。 |
| lottery_within_group | 是 | 发起人描述，未经官方核实 | 优先级处理后进行随机分配。 |
| preset_occupies_seat | 否 | 系统假设 | 预置是否正式占用课位未经核实，默认不占位，只作为预填志愿影响学生选择。 |
| preset_releasable | 是 | 系统假设 | 假设学生可以撤销或修改预置课程。 |
| round2_enabled | 是 | 发起人描述，未经官方核实 | 第二轮继续选课与分配；具体轮次数量与规则未核实。 |

## 3. 机制定义

| 组别 | 机制 | 作用 |
| --- | --- | --- |
| A | 现行机制基线 | 培养方案只推荐必修，随后完整执行两轮选课，作为现行做法的简化模拟 |
| B0 | 一次性优化（无交互） | 同一优化器只用初始志愿，用来扣除“优化器本身”的贡献 |
| B | 规则式集体规划 | 透明规则选择询问对象，用来判断收益是否只来自额外交互 |
| C | AI 选择问题 | LLM 在 B 的候选问题集与预算内挑选询问对象 |
| D | 完整信息参照 | 披露全部隐藏偏好，估计信息缺口上限，不可部署 |
| E | AI 协调提案 | LLM 读取全局状态与学生记录生成结构化提案，经合法性校验、学生确认后才影响搜索 |
| F | 规则协调提案 | 规则生成同类提案，与 E 共用校验器、执行器、优化器与模拟 |

控制器可见状态为每名未满足需求的学生给出 `admissible_course_ids`（可直接询问的课程）与 `admissible_swaps`（需先释放冲突课程才能询问的课程对），这两份清单与校验器使用同一套可见规则；校验器仍独立判定，非法动作被逐个丢弃，全部非法才整案拒绝。第一版实现没有把这些事实交给控制器：8 个种子共生成 36 份提案，只有 1 份通过校验且未获学生确认，因此 E 的最终效用与 B0 在全部 8 个种子上完全相同（已逐行核对）。该运行已归档在 `archive_rejected_action_space/`，作为“控制器缺少合法性信息时提案机制退化为空操作”的失败记录。
| G | 等预算随机询问 | 消融：同样多的询问，但随机选择对象，用于分离“询问数量”与“问得准” |
| H | 获取信息不改预置 | 消融：仍然询问，但答案不写回可见状态，最终求解的输入与 B0 完全相同（4 个种子上 H 与 B0 的效用逐个相等）。它只分离出“沟通成本”，没能分离“信息”与“重新优化” |
| I | 规则语义需求解析 | 用关键词/别名表把散文式学生记录匹配到课程介绍，直接扩展优化器候选，不询问 |
| J | AI 语义需求解析 | 同一接口换用 LLM 读取记录与课程描述，逐条给相关度、理由与原文证据，不询问 |
| K | 真实需求标签参照 | 用隐藏真值标签充当“完美解析器”，走同一映射与同一上限，仅用于测量剩余空间，不可部署 |

符号检验只问“在非平局场景里前者赢的次数是否多于抛硬币”，不问赢的幅度。本轮最多 4 个非平局场景，即使 4 战全胜 p 也只到 0.125，达不到 5% 显著——因此这些行只能报告方向，不能报告效果。

E−F 是本实验的核心判据：它比较的是“LLM 生成提案”与“规则生成同类提案”，两者的校验器、执行器、优化器、询问预算与随机情景完全相同。若 E 未稳定优于 F，只能说明提案机制有效，不能说明收益来自大模型。

## 5A. 需求解析位点（I 规则解析 / J AI 解析 / K 真值参照）

- 这一位点一个问题都不问，只改变“进入优化器的需求清单从哪来”，与 C（挑问题）、E（协调提案）两个已关闭位点正交。
- 两种解析器共用同一道桥：`predicted = 40 + 55 × 相关度`，相关度 ≥0.35 才允许进入，每人至多 8 门，绝不覆盖学生自己申报的分数，也绝不改动必修课处理。先修资格、容量、时段、必修清单全部由 `institution.py` 与校验器判定，解析器只能扩展候选，不能放松硬约束。
- 隐藏真实分数只被 K 使用（逐行标注 `hidden_utility_used`），K 不可部署，只回答“同一个接口下完美解析器能走多远”。

- 反稻草人核查：改写后的 12 种说法里，现有手工别名表能恢复 3 种（25%）。规则基线不是空壳，但也不是无损解析——测的是“免手工维护别名表的泛化能力”，不是“规则做不到”。

| 学生说法 | 对应主题 | 规则别名可恢复 |
| --- | --- | --- |
| 让模型自己从经验里学会规律 | 机器学习 | 否 |
| 用概率判断一个结论有多可信 | 统计 | 是 |
| 把麻烦的问题解得又快又省 | 算法 | 否 |
| 把资料存进可靠的库里并取得快 | 数据系统 | 否 |
| 让机器读懂文本 | 自然语言 | 是 |

## 8. 结论边界

- 总效用更高不等于更公平；请同时查看 p10 学生效用、必修满足率与分组效用。
- 所有效用都在合成隐藏偏好上计算，不能外推为真实校园效果。
- LLM 组任何一次回退到规则策略的运行都被标记为无效，并从均值与配对比较中剔除。
- D 组不可部署，它只用于估计“信息缺口”还能贡献多少，而不是证明某种制度更优。
- A/E/F 等机制的先后顺序由制度规则表决定；其中标注为假设的规则一旦与真实制度不符，结论需要重跑。
- 预置方案默认不占用正式课位（preset_occupies_seat=否）；若学校规则改为占位，需要重新评价。
- 学生回答由确定性模型给出且默认诚实，不含策略性隐瞒，因此询问收益是模型上限而非真实现场。
- `proposals_valid` 的口径是“至少保留一个合法验证动作”，不是整案完全合法；被丢弃的非法动作单独记在 `actions_rejected`，整案拒绝记在 `proposals_rejected`。
- 控制器可见状态里的 admissible 清单与 F 组候选都来自同一套可见规则的可计算集合；E 与 F 的差别在于由谁决定为谁组合、优先级排序与何时停止。若 E 只与 F 打平，只能说明这套协调机制本身可运行，不能说明收益来自大模型。
- E 与 F 共用同一份规则解析的需求模型，避免“需求理解”和“提案生成”两个变量同时变化；LLM 语义需求模型在界面与单元测试中单独可运行，但未参与本对照，以免混淆归因。
