## 0. 为什么会有第二个实验（不得当作事后补救）

任务要求 AI 交付的是**需求模型**：学习目标、课程相关性、可接受替代项、需求类别、不确定性。
v1 实现里只有后三类的一半：相关度/理由/原文依据/不确定性有，`需求类别` 是采纳阈值算出来的
（`semantic_needs.py:377`），`学习目标` 是正则摘出来的模板原句且三臂完全相同，`可接受替代项`
与模型自己识别的歧义根本没进记录（`semantic_needs.py:430-437`）。这些缺口在 v1 判定落盘之前
就无法回补：v1 的冻结规则（`results_semantic_need/PREREGISTRATION_SEMANTIC_NEED.md` §3）规定
提示词与 `PARSER_VERSION` 一经登记不得改动，改动即构成新的处理，必须开发集与测试集全部重跑。
所以补齐字段的做法只能是**另立一个处理**，另立一个实验，绝不能回头改 v1 那条已经判完的臂。

时间顺序如实登记：本文件写于 20:35，v1 的 `FROZEN_VERDICT.md` 尚未产出（预计 21:05 之后），
因此 v2 的字段集与判据没有被 v1 的测试集结果影响。v2 的字段集来自任务书与代码审计，
写于 20:20 之前。

## 1. 研究问题

让读者（LLM 或规则）在同一份散文记录上交付**完整需求模型**之后：

- 需求识别质量是否提高（重要需求召回、需求识别 F1）？
- 新字段本身是否可信（点名课程识别率、可接受替代项判断正确率、学习目标原文可核对率、
  自称"明确要求"被规则纠正的比例、类别标签与隐藏真值的一致性）？
- 由这些判断生成的预置课表，在完整两轮选课后是否得到更高的最终总效用？

## 2. 单变量控制

I2 与 J2 共用下列全部要素，唯一差别是读记录的那个解析器：

| 要素 | 取值 |
| --- | --- |
| 学生与课程 | 同一 `generate_world(n_students=72, seed=s)` |
| 硬约束 | 先修资格、容量、时段、必修清单仍由规则系统判定；相关度行全部走 v1 的 `validate_relevance` |
| 进入优化器的接口 | `predicted_visible` 一字未动：同一映射 `分数 = 40 + 55 × 相关度`，同一采纳阈值 0.35，同一每人至多 8 门 |
| 优化器 | 同一个 `solve_assignment`（CP-SAT，workers=1，max_seconds=6） |
| 评价对象 | `simulate_selection` 两轮后的最终课表，配对随机情景 `seed×1000+17+i`，replicates=3 |
| 询问预算 | 两臂均为 0 次询问 |

**必须写清的一件事**：新增的学习目标、点名的第一志愿、可接受替代项、需求类别**都不进入优化目标**，
它们只进可追溯记录与新指标。因此若 J2 与 I2 的最终效用出现差异，唯一合法解释是"换了提示词以后
相关度变了"，不得叙述成"因为 AI 识别出了可接受替代项所以课表变好"。

K2 与 v1 的 K 一样使用隐藏真值标签，走完全相同的接口与上限，仅作天花板参照，不可部署。
隐藏真实偏好（`true_scores`）从不进入 I2 或 J2 的提示词；它只用于事后给标签打分。

**2026-10-17 20:57 补记（第一批 v2 数据存在之前，用开发种子 1 的规则臂现跑发现，不是事后解释）**：

- **行级"明确要求"对三臂都是结构性空集**。该标签只在学生逐字点名某门课时才合法，而语料里唯一被点名的课就是学生自己申报的专业选修——那门课必然被 `validate_relevance` 以"已由学生自己申报，无需推断"拒绝，永远进不了相关度表。所以 `need_class_distribution["明确要求"].rows` 预期恒为 0，**这不代表模型不会分类**；真·明确要求由 `explicit_request` 字段承载，用 `truth_first_choice` 判对错。测试 `test_row_level_explicit_class_is_structurally_unreachable` 把这条钉住。三臂之间真正有鉴别力的类别差别只剩"一般偏好 vs 仍有歧义"（后者只在解析器给出低于 0.35 的相关度时出现），v2 的结论范围据此收窄。
- **K2 的三项学习目标指标记为 `null`**（`goal_metrics_applicable=false`）：真值臂按接口只有分数标签，没有自然语言目标，写 0 会被读成"真值参照在学习目标上比 AI 差"。
- 规则臂在种子 1 上产生 226 条 `problems`，逐条看全是合法性拒绝（自申报、先修不达、必修不可推断），与 v1 同类，不影响 F1 口径，但会原样进报告的可靠性段落。

## 4. 主判据与停止规则

- **主判据**：J2 − I2 的最终总效用，只在测试种子 7-26 上算，双侧精确符号检验，p < 0.05 判"有增益"。
  20 个非平局对至少 15 胜（`_sign_threshold(20)`）。
- **次要判据（只做描述，不得用来翻转主判据）**：需求识别 F1、重要需求识别召回、重要需求最终满足率、
  p10 学生效用、以及 §1 的新字段指标（点名识别率、替代项正确率、类别纠正率、类别与真值一致性）。
- **停止规则**：跑满 20 个测试种子即停，无论 p 为何值都不追加种子，不换指标。
- **唯一允许的行剔除**：`llm_fallback=True` 的 J2 行；剔除数量与种子编号必须披露。
- **功效声明**：n=20 只能检出很强效应；点估计小、±2SE 跨 0 时结论是"本设计测不出差异"，不是"无差异"。
  阴性结果照原样发布。

## 5. 事前声明的风险

1. **模板天花板**：学习目标、点名的课程、"选不上也愿意考虑其他课"这三样都是生成器逐字写进记录的，
   规则臂可以无损读出来。因此这些字段上不该期待 AI 占优；AI 唯一可能赢的地方是把日常说法
   （"让模型自己从经验里学会规律"）映射到课程介绍。这一条与 v1 §6.2 同源，必须写进结论。
2. **非逐位复现**：v1 §7.4 实测同一种子跨进程重跑，J/K 的总效用会浮动数十点，与 J−I 逐种子差值同阶；
   误差地板未标定。v2 照原样判定，并在结论里保留"边界附近的差值不可读作证据"。
3. **并发污染**：v1 批次跑完之前不启动 v2 的任何东西（求解器有 6 秒墙钟上限，同机会改变结果）。
   v2 的每一次运行都必须在其日志里记录起止时间与当时是否有其他求解进程。
4. **配额**：26 个种子 × 72 份档案 = 1872 份，6 份/次 = 312 次调用，上游 20 次/分钟 ⇒ 至少 16 分钟节流；
   缓存 `semantic_cache/llm_relevance_v2.jsonl` 与 v1 完全分离，键含 `semantic-need-v2`，
   崩溃重启不重复计费。

## 6. 交付判定的写法

判定文件由加了 `--results-dir/--out` 参数的 `analyze_semantic_need.py` 生成，种子不全时拒绝出判定。
README 里 v2 一节必须与 v1 一节并列出现，且明确：v1 是任务书原始设计（只判相关度）的预注册检验，
v2 是把字段补齐成"需求模型"之后的第二次预注册检验；两者的主判据互相独立，
谁都不能用来宣布对方被推翻。若 v2 仍为阴性，结论是"把需求模型做完整也没有换来可复现的最终收益"，
而不是"实验没做好"。
