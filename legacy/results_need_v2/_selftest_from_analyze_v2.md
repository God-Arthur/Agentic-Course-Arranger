## 6. 已验证 / 未验证

- 已验证：完整需求模型的每个字段都有可核对来源，模型自称的内容逐条过规则校验，非法推断被丢弃并计数；三臂共用同一分数映射、同一优化器、同一两轮模拟；隐藏真实分数从不进入 I2 或 J2 的提示词；LLM 失败必回退并标记为不可用作 AI 证据。
- 未验证 / 无法由本实验回答：真实学生是否真会这样写 `.skill`（记录为合成改写）；培养制度是否如假设；把课程介绍换成真实教务数据后别名表与提示词是否需要重做；n=20 的功效只够检出很强效应。
- 求解器可重复性的边界：`--solver-max-seconds` 是墙钟上限且单 worker，撞上上限时交出的是**未证优的可行解**。同一颗种子、同一配置、同一个臂已经实测过目标函数值与最终效用都能移动（核对过程与数值见 README §7C；那是参照臂 K2，不在主判据里）。因此**单颗种子的效用差不能当成解析器的效应**，只有配对胜局数与跨种子合并区间可以。三臂共用同一上限与同一配对情景，但「未证优」在三臂之间不是同分布的噪声：本批测试种子上 solver_status 为 OPTIMAL 的行数实测为 I2_规则完整需求模型 20/20、J2_AI完整需求模型 14/20、K2_真实需求标签参照 4/20（分母是该臂可用的行数，由判定脚本从落盘 CSV 现算）。撞上上限的那一臂交出的是可行解而不是最优解，所以 J2 − I2 里混进了「搜索难度随解析结果而变」这一系统成分：判读时按混杂处理，不能只当作两臂同分布的随机抖动；符号检验的配对结构不受影响，但 ±2SE 区间里天然含未收敛的成分。
- 与 v1 的关系：v1 检验的是任务书的原始设计（只判相关度），v2 检验的是把字段补齐成需求模型之后是否换来了最终收益。两者主判据互相独立，谁都不能用来宣布对方被推翻。
