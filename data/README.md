# 课程数据格式

`data/courses.json` 自 2026-10-19 起是**教务系统抓取的真实开课目录**（2026-2027 秋冬学期），由
`../tools/build_courses_from_zju.py` 从 `zju_catalog/` 的抓取产物生成，整文件重建；上一版合成数据留在
`courses_synthetic.json`。`capacity` 用同日 10:25–10:37 抓到的「最大容量」快照（min 3 / 中位 40 / max 480）；
同批数据里的「余量/已选人数」是实时占用，**没有**接入模拟——每班都从空班起算（口径见文件内 `_meta.capacity_source`）。

`data/courses_k10.json` 是同一份目录把**每个教学班容量 ÷10**（最小 1 座）的微缩版：
2173 门课 / 4291 个教学班不变，座位从 243,538 降到 24,228（min 1 / 中位 4 / max 48）。
人数与容量必须同比例缩，否则稀缺结构消失，见「微缩实验」一节。

装载校验只认下面这些字段，多余字段（`_meta`、`teacher`、`room`、`term_flag`）会被忽略。

```json
{
  "courses": [
    {"course_id": "CS101", "name": "数据结构", "category": "专业课", "major": "计算机科学与技术"}
  ],
  "sections": [
    {"section_id": "CS101-01", "course_id": "CS101", "capacity": 60,
     "slots": ["Mon-1", "Mon-2"]}
  ],
  "plan": {
    "majors": ["计算机科学与技术"],
    "recommended": {
      "计算机科学与技术": {"思政类": 1, "外语类": 1, "专业课": 2, "通识与体育类": 1}
    }
  }
}
```

字段说明：

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| courses[].course_id | 是 | 课程唯一编号 |
| courses[].name | 是 | 课程名（展示用） |
| courses[].category | 是 | 九类之一：思政类 / 外语类 / 计算机通识类 / 自然科学通识类 / 专业课 / 专业基础课 / 通识核心课 / 通识选修课 / 体育课 |
| courses[].major | 否 | 开课专业；"专业课"用于"本专业学生选专业课"优先级 |
| sections[].section_id | 是 | 教学班唯一编号 |
| sections[].course_id | 是 | 必须指向已有课程 |
| sections[].capacity | 是 | 正整数容量（本项目取教务快照的「最大容量」列；接口里的 `rs`/「余量」是剩余名额，不是容量） |
| sections[].slots | 是 | 时间槽列表，`Mon-1` … `Fri-13`（也接受 `周一-3`；上午 1-5、下午 1-5=6-10、晚上 1-3=11-13；节次直接对应 1-13；网格只有周一至周五，周六/周日班在转换阶段剔除） |
| plan.majors | 否 | 专业列表（合成学生会从中抽取） |
| plan.recommended | 否 | 每个专业本学期各类别的必修门数；分类键也可写"通识与体育类"表示三类合并计数 |
| plan.recommended_by_year | 否 | `{专业: {学年: {类别: 门数}}}`，实验人口按 (专业, 学年) 加权铺开时读它 |
| plan.need_rules | 否 | 需求侧的非常规口径（外语比例池、体育 standing rule、排除学年、门数上限），见下 |

注意：

- 一个学生同一类别（合并后）的修读目标不能超过该类别的课程数，否则无法满足，会如实反映在未满足指标里。
- 一个教学班可安排多个时间槽；同一课程的不同教学班时段可以相同（同时段多班是允许的）。
- JSON 中允许附加字段（如本文件数据里的 `_meta`），装载时会被忽略。

## 需求口径（2026-10-20 落到数据里）

`plan.recommended` / `plan.recommended_by_year` 与 `plan.need_rules` 由转换器按方案原文重算，四条都在文件里可查：

| 规则 | 值 | 为什么 |
| --- | --- | --- |
| `language_share_per_student` | 0.33 | 方案原文里外语类是**四年累计 3–6 学分的阶梯池**，大英Ⅲ/Ⅳ 不是每学期必修；按每学期比例摊给约三分之一学生 |
| `pe_courses_per_student` | 1 | 方案要求大一到大三**每学期选 1 门**体育，但不列课名（grid 行数恒为 0），只能作 standing rule 交给合成器，加进合并桶 `通识与体育类` |
| `exclude_grades` | 四、五 | 大四/大五不选课（不造 graduating 标记） |
| `courses_per_student_cap` | 8 | 方案 CSV 的 秋/冬 行是该学年该类别的**候选课池**，不是必修清单——计算机科学与技术 三 列出 25 门 / 64.5 学分。按各类别原门数等比压到每学期 8 门（非零类别至少 1 门）。不压则两轮选课下**所有学生必然缺口**，满意度失去区分度（压前 n=10 冒烟：均分 30.5；压后：54.2） |

已知解析瑕疵仍在：方案里"一(秋冬)"这类合并单元格被记成了 `一(冬)`，秋/冬两列不能单独取信，
但"秋或冬非空"的筛子照样命中，门数没数错。另有 `二/三` 学年是**同一份 2026 级方案的跨届代理**
（只爬到 2026 级，`_meta.year_proxy_assumption` 记下了这个假设）。

压平后在 k10 数据上按 1800 人（前三届 18000 ÷ 10）铺开的需求/座位对照，人均目标 10.88 门（min 3 / max 15）：

| 类别 | 需求门次 | 座位 | 缺口 |
| --- | --- | --- | --- |
| 计算机通识类 | 1732 | 670 | **1062** |
| 外语类 | 1558 | 781 | **777** |
| 专业基础课 | 2110 | 1879 | **231** |
| 思政类 | 2786 | 2791 | −5 |
| 自然科学通识类 | 2075 | 2453 | −378 |
| 通识与体育类 | 2107 | 5076 | −2969 |
| 专业课 | 7209 | 10578 | −3369 |
| 合计 | 19577 | 24228 | 盈余 4651 |

整体座位多于需求，稀缺是**分类结构性的**：计算机通识与外语两个桶装不下，通识/体育/专业课有余座。
这正是实验要考察的分布，不是数据缺陷。

重建两份数据（只读 zju_catalog，输出到 /tmp，人工核对后再落地）：

```bash
bash tools/rebuild_zju_datasets.sh
```

## 同目录的其他产物

`courses.json` 之外的文件都是人数推测与旧规模测试的产物，装载器只读 `courses.json`：

| 文件 | 生成命令 | 内容 |
| --- | --- | --- |
| `major_sizes.json` | `.venv/bin/python tools/estimate_major_sizes.py --per-grade 6000 --out data/major_sizes.json` | 各专业年级人数（**推测值**：2026 浙江招生计划直接命中 + 大类计划等分补齐 + 全国放大 1.94 倍），`per_grade` 合计 6000、`all_grades` 合计 24000 |
| `scale_test_24000.json` | 生成脚本 `tools/scale_test.py` 已删除 | 旧规则路径规模测试报告（按类别的需求/缺口/供给/满员班数），**数字不作数**，见下 |
| `scale_test_6000_g1.json` | 同上 | 只有 2026 级 6000 人的同一测试，同样不作数 |
| `zju_build_report.json` | `build_courses_from_zju.py --report data/zju_build_report.json` | 转换阶段的分类分布与剔除统计 |

那两份 `scale_test_*.json` 作废有两个独立原因：它们走的是规则回退路径（`_static_round`，不经 LLM），
属于发起人 2026-10-20 明令禁止的本地模拟；而且它们把 `二/三/四(秋冬)` 的需求也拿来跟 `2026-2027_1`
这一个学期的座位比。按培养方案原文更正后的需求口径（外语类是四年 6 学分池、体育前三年每学期 1 门、排除大四）
与新旧对照表，见 `../README.md` 的「需求口径」一节。人数始终是推测值，所以任何绝对数字都只能读成
"在该人数假设下的算术结果"，类别之间的相对比较才是它能回答的问题。
