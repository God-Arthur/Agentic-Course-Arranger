AI 预置课表规划系统

教务预置 → 两轮选课模拟（LLM 填志愿 + LLM 筛中签）→ 满意度复盘改写，为每名学生生成整学期的预置课表
项目介绍

真实选课流程是：教务系统先给每名学生生成一份预置课表，然后学生进入两轮选课（每轮可退课、可选课， 每轮结束后按「毕业年级 > 转专业 > 即将换校区 > 本专业学生选专业课 > 其他」的优先级分组与志愿序号筛选， 同组内名额不足时给谁由模型判断）。 本项目研究的正是这份预置怎么生成：把学生提交的 .skill 记录解析成结构化需求模型，为每名学生生成覆盖全部课程类别的预置课表； 再用两轮选课模拟评估它——每轮先由 LLM 逐生填报志愿，再由 LLM 扮演教务筛选器决定本轮中签名单，最后由 LLM 打分； 根据满意度复盘改写预置（把最差一批学生的预置连同上一轮结果交回模型重新生成），保留历史最好的一轮、重复若干次， 最终输出每名学生的完整预置课表。 整条链路只有一个通路，没有规则兜底：任何一次 LLM 调用失败或输出不合规都会直接终止本次演示并如实报错。 代码只做事实校验——教学班是否存在、还有没有空位、是否重复持有同一门课、时间是否冲突、志愿是否超份数上限， 被拒的授予计入 sanitized 并原样出现在事件流里；容量、时段、志愿上限这些制度约束模型无权改。 谁中签由模型决定，所以同一份输入两次跑出的名单可能不同，结果不可复现。 真实开课目录有 4000 多个教学班，无法整表送进模型：学生志愿那一步每轮只把该生尚未满足类别的候选教学班交给 LLM （上限 80 行、满员班不列、配额在各待满足类别间轮流分配，某类被省略多少会在清单里如实标注）； 筛选器那一步只把有学生填报的教学班及其志愿名单交给模型（上限 300 行，未列出的部分同样如实标注）。
