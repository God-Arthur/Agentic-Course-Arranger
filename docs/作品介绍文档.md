# 作品介绍文档


## 一、作品名称

**面向真实开课目录的 AI 预置课表规划与选课模拟系统**

## 二、核心关键词

预置课表生成；大语言模型（LLM）；两轮选课行为模拟；稀缺容量分配；培养方案约束

## 三、作品概要

本作品把高校选课的**前置环节**——"学生进入选课系统之前，教务系统已经替他排好的那张预置课表"——做成一条完全由大语言模型驱动的可执行通路，并在**教务系统抓取的真实开课目录**上验证它跑得通、算得清成本。

真实流程是：教务先生成预置课表 → 学生进入**两轮**选课，每轮可退课、可提交志愿 → 一轮选课时间结束后按优先级分组（毕业年级 > 转专业 > 即将换校区 > 本专业学生选专业课 > 其他）筛选中签。以往被当作黑箱规则的"预置怎么来、名额给谁"，在本作品里全部变成模型的显式决策，并留下可审计的证据链：

1. **LLM 解析需求**：把学生 `.skill` 自然语言档案解析成结构化需求（必修类别、目标门数、回避时段）。
2. **LLM 生成预置**：为每名学生排一张覆盖**全部课程类别**的预置课表，而不只是培养方案的推荐课。
3. **LLM 模拟两轮选课**：每轮一次"志愿 + 退课"调用、一次"教务筛选器"调用——**谁中签由模型判定**，优先级分组、志愿序号、每班剩余名额都如实喂给它。
4. **LLM 逐人打满意度**：0–100 分加自然语言理由。
5. **LLM 复盘改写**：把打分最差一批学生的预置释放，连同上一轮结果与评分理由交回模型重新生成，保留历史最好的一轮，重复若干轮。

代码在这条链路上**不替模型做任何取舍**，只做事实校验：教学班是否存在、是否还有空位、是否与已持有课程重复、时间是否冲突、志愿是否超过份数上限；被剔除项计数并原样出现在事件流里。任何一次调用失败或输出不合规直接终止运行——**系统内不存在规则兜底通路，也不存在本地抽签**。

数据侧接入 2026–2027 学年秋冬真实目录：**2173 门课程 / 4291 个教学班 / 160 个专业的培养方案目标**（容量取抓取时刻快照，按发起人口径从"已选 0"开始模拟；可排时段周一至周五 13 节，不考虑周末）。学生 `.skill` 档案为合成——教务不提供学生真实偏好，这一点在所有文档中均如实标注。交付形态两套：单页 HTML 演示（配置接口、设人数、看逐人课表与两轮结果）与可断点续跑的规模实验工具（分阶段检查点、并发调用、每轮落盘）。

## 四、解决的核心痛点

| 痛点 | 本作品的处理方式 |
|---|---|
| 预置课表由规则拼装，个体差异在第一轮就被抹平：同专业同届拿同一套模板 | 逐人一次 LLM 预置调用，输入是本人 `.skill` 解析出的需求模型与该专业培养方案目标 |
| 供给 < 需求时"名额给谁"是稀缺分配问题，规则抽签无法解释也无法复盘 | 筛选器拿到优先级分组、志愿序号、每班余座三项事实后由模型给出名单；每次拒发都带原因、可逐条回看 |
| 学生需求以自然语言存在，人工结构化成必修/选修/回避时段成本高、口径不一 | LLM 解析需求，解析结果与原始文本一并落盘，便于抽查口径是否漂移 |
| 制度口径（九类课程、通识核心/通识选修/体育合并计志愿、每班 3 志愿上限、优先级分组）散落在人脑和文件里，没有可执行版本 | 口径以常量与数据字段落在代码与 `data/*.json` 的 `need_rules` 中，可复算、可版本化 |
| 排课方案改动无法预演：调容量、改类别归属之前不知道谁会受影响 | 容量按 ÷k 缩放即可构造稀缺的迷你世界，并用分级缺口指标（未满足的必修名额总数）替代"是否失败"的二值判断 |

**需要如实说明的边界**：本作品当前证明的是**纯 AI 通路在真实教务规模上可运行、可审计、可复盘**，不是"AI 比规则算法排得更好"。两者要用同一把尺子比才有意义，而满意度分数本身出自模型、跨通路不可直接比较。

## 五、落地应用场景

1. **选课前的预演**：正式开放选课前用真实目录预演一轮，看哪些必修名额必然抢不到，提前扩容或增班。
2. **培养方案合规自查**：把目标类别/门数与开课目录的实际供给放进同一网格，缺口按专业、按学年直接暴露（本目录在 ÷10 缩尺下，计算机通识、外语、专业基础三类结构性短缺同时存在）。
3. **稀缺与政策情景推演**：容量倍数、类别合并规则、优先级分组都是数据字段，改一个参数即可重跑同一批学生并比较受影响人数。
4. **选课咨询与解释**：逐人留存"预置为什么这么排、谁中签为什么给他、哪一次授予被拒以及原因"的事件流，可作为向学生的解释材料。
5. **研究载体**：同一输入下"模型判定中签"与"规则抽签"的对照、多随机种子配对比较，都是可直接在本项目上追加的实验臂。

## 六、预期应用成效

**已经量到的**（均可在仓库内复算，完整口径见支撑材料《技术路线》与《实验披露_n1800》）：

- 真实目录与人口口径接入完成：2173 门 / 4291 教学班 / 160 专业 / 5×13 时间网格；÷10 缩尺档 1800 人覆盖 160 个专业，文理工农医均有。
- **规模档正式跑已完成**（1800 人、容量 ÷10、seed 7、2 次迭代完整闭环）：全链路 0 次退避，进程级致命失败 11 次全部由检查点续跑消化；最终 1 797/1800 人必修名额未填满，人均持有 3.58 门课。
- **成本与规模的关系已量化**，这是决定"能不能用"的关键一手数据：**8.31 次调用每生**（n=100 标定得 8.35，被 18 倍规模验证），分段吞吐短提示 76–89 次每分、重提示仅约 25 次每分，筛选器单块一次调用最长 1936 s。由此得到的结论是：本系统适合**选课前的离线预演与政策推演，不适合当选课现场的实时组件**——把这条边界写清楚比报一个好看的分数更有价值。
- **两条负面结果如实报道，不包装**：① 满意度轮间分差（30.8 → 35.7）出自模型打分且混着抽样波动，**不能**写成"优化有效"，判定需要配对多随机种子；② 复盘改写之后那一轮的第 1、2 轮事件流 sha256 完全相同、全程退课 0 次、拒发 0 次——**"两轮选课模拟起了作用"这一条已被自己的数据反证**，根因是 ÷10 之后志愿池与预置占用班几乎不重叠、筛选器面对的是没有竞争的情形。

**下一步（已有可失败判据）**：给预置与复盘阶段补阶段内落盘，使配额损耗从区间变成单值；在志愿池与预置高度重叠的参数下重跑，把"两轮机制"真正测出来；产出按 (专业 × 类别 × 学年) 的**供给侧扩容建议表**；同输入配对多随机种子检验复盘是否有效。
